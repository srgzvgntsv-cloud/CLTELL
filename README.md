# CLTELL — Telluric Line Correction using SLD

CLTELL is a Fortran program for recovering stellar spectra by modeling and removing telluric absorption. It combines forward modeling of Earth's atmospheric transmission with **Spectral Line Deconvolution (SLD)** to refine the telluric-line profiles. The program has no graphical interface; its parameters are specified in configuration files.

## Features

- Forward modeling of telluric absorption using standard atmospheric models and the **HITRAN** molecular-line database.
- Refinement of line profiles with SLD to mitigate inaccuracies in atmospheric parameters and line modeling.
- Treatment of multiple molecular species, including H₂O, O₂, and CO₂, with separate SLD profiles.
- Gaussian instrumental broadening.
- Joint modeling of stellar and telluric spectral components.
- Processing of archival observations when detailed meteorological measurements are unavailable.

## Requirements

The project supports **Windows** (developed with Compaq Visual Fortran) and **Linux** (built with Intel Fortran Classic). The Linux build process automatically applies the necessary compatibility changes to temporary copies of the source files, leaving the original code unchanged.

| | Windows (original build) | Linux (tested in Ubuntu 22.04 / WSL) |
|---|---|---|
| Fortran compiler | Compaq Visual Fortran (`df.exe`), as referenced by `CLTELL.dsp` | Intel Fortran Classic (`ifort`) |
| Numerical libraries | Bundled `CXML.LIB` (Compaq Extended Math Library) | BLAS and LAPACK (`libblas-dev`, `liblapack-dev`), or a compatible numerical library |
| Compatibility code | Original `DFPORT` compiler module | A `DFPORT_COMPAT` module generated by `build_linux.sh` for the used `CLOCK()` function |
| Target | 32-bit Windows, according to the original project settings | 64-bit Linux |


### Building on Windows

Clone the repository or download the archive.

Open a terminal in the root folder of the project (e.g., `CLTELL-main/`).

Compile:

```bash
gfortran -O3 -o CLTELL.exe CLTELL.f90 *.f90 CXML.LIB
```

The executable `CLTELL.exe` will be created in the current folder.

**Note:** For Windows, you can use a pre-built binary from the `bin/` folder if provided.


## Building on Linux (Intel Fortran)

The Linux build was tested with **Intel Fortran Classic (`ifort`) on Ubuntu 22.04 under WSL**, linked against the system BLAS and LAPACK libraries. The repository includes a **`build_linux.sh`** script to automate source compatibility adjustments and compilation.

### 1. Install the dependencies

Install Intel Fortran Classic (`ifort`) and make it available in the shell, then install BLAS and LAPACK:

```bash
sudo apt update
sudo apt install -y libblas-dev liblapack-dev python3
```

If `ifort` comes from Intel oneAPI and is not on your `PATH`, initialize the oneAPI environment first.

### 2. Run the build script

From the repository root:

```bash
chmod +x build_linux.sh
./build_linux.sh
```

The script automatically:

- Copies the Fortran source files to `.build-linux/` to preserve the original sources.
- Replaces `use DFPORT` with `use DFPORT_COMPAT` in those copies.
- Generates the compatibility module `DFPORT_COMPAT.f90`, which provides the `CLOCK()` function used by CLTELL.
- Resolves the four argument-name conflicts in `HITRAN_DEPTH_FILTER` (`gamma_air`, `gamma_self`, `n_air`, `d_air`) in the temporary build copy, leaving its calculations unchanged.
- Compiles the files in module-dependency order and links them with `-llapack -lblas`.

The resulting executable is **`CLTELL_linux`**, placed in the repository root. The original source files are unchanged.

### 3. Verify the executable

```bash
file CLTELL_linux
ldd CLTELL_linux | grep 'not found'
```

`file` should report a Linux ELF executable. If `ldd` produces no matching lines, no missing shared libraries were reported.

**Note:** The successful test build was originally carried out step by step; the automated `build_linux.sh` script follows that sequence but should also be tested from a clean checkout.

## Preparing the data

### HITRAN line database

Extract **`Hitran_database.par`** from the repository's `Hitran_database.rar` archive and place it in the directory from which the program expects to read it (for the setup below, the repository root alongside the executable).

For example, extract the archive with `unrar`:

```bash
unrar x Hitran_database.rar
```

### Observed spectrum and stellar-line database

The main configuration refers to a working directory, for example `examples/`, containing the input files:

- **Observed spectrum:** typically a text file containing wavelength in Å and normalized flux (two columns); FITS support depends on the input routines and has not been verified in this build.
- **Stellar-line database:** files with extensions `.dbs`, `.dir`, and `.lin`, generated separately (see `SLDinit/`):
  - `.dbs` — unformatted theoretical stellar-line profile database;
  - `.dir` — unformatted auxiliary database information;
  - `.lin` — text line list containing wavelength (Å), line identifier, and central depth.

> **Linux path convention:** use forward slashes in paths, e.g. `examples/` instead of `examples\`.

## Configuration

CLTELL reads **`SLD.config`** and **`config.ini`**. Keep both in the directory used to launch the executable unless the source code has been modified to read them elsewhere.

### `SLD.config` — spectrum-specific parameters

```text
examples/                 ! Working directory
vega_normalized.dat       ! Input spectrum filename
none                      ! Height/relative-humidity file (none = unused)
2 1                       ! Fitting mode and component selection
6000.0 6400.0             ! Wavelength interval (Å)
21                        ! v sin i star (km/s)
100000                    ! Spectral resolution
60                        ! Number of SLD-profile points
Vega                      ! Stellar-line database name
1                         ! Number of line-intensity groups
'O2  ': 0.3               ! Groups by intensity (Molecule: group1 < intensity < group2)
```

The two mode parameters are:

- **Selection mode:**
`0` = lines (Levenberg–Marquardt method). Prioritized, but sensitive to the number of lines;
`1` = molecules (Levenberg–Marquardt method). More physically justified if not all star lines are identified (missing from the database);
`2` = lines (golden section method). The fastest, works with any number of lines;
 
- **Components:**** `0` = stellar + telluric; `1` = telluric only; `2` = stellar only.

Set the number of groups according to the expected number of entries in the groups. The example uses **one** entry (`O2`: 0.3), which means that the lines of the `O2` molecule will be divided into two groups based on intensity: up to 0.3 and above 0.3. The basic configuration is without groups. This means that for a single molecule or atom, there will be no groups of lines ordered by intensity.

### `config.ini` — algorithm settings

```text
2            ! Number of iterations for line intensity correction (golden section method)
1	     ! Search for line shift in velocity space (=1 — yes, /=1 — no)
-3.0         ! Maximum line shift to the left in velocity space (km/s)
3.0          ! Maximum line shift to the right in velocity space (km/s)
0.001        ! Minimum line intensity multiplier (golden section method)
1000.0       ! Maximum line intensity multiplier (golden section method)
1.0          ! SLD profile step for stellar lines (km/s)
0.1          ! SLD profile step for telluric lines (km/s)
0.01 0.0     ! Tikhonov regularization parameters
0            ! Observatory altitude (m)
2            ! Atmosphere model: 1 — equatorial day; 2 — night in mid‑latitudes; 3 — polar winter
2000         ! Atmosphere grid height step (m)
```

The examples above illustrate the expected structure; use values appropriate for your data and experimental setup.

## Running CLTELL

Run from the directory containing the configuration files and HITRAN database:

**Linux:**

```bash
./CLTELL_linux
```

**Windows (legacy build):**

```bat
CLTELL.exe
```

The program requires no command-line arguments. It reports progress during processing and writes output files to the configured working directory.

### Output files

| File | Description |
|---|---|
| `*.no_tell` | Spectrum corrected for telluric absorption (wavelength in Å, normalized flux). |
| `*.result` | Modeled observed spectrum (wavelength in Å, normalized flux). |
| `*.sld` | Recovered SLD profiles for configured line groups (velocity in km/s, profile values). |
| `scale_abundances.dat` | Molecular-abundance scaling factors; generated on first run and reused if present. |

### Example workflow

1. Confirm that `examples/` contains `vega_normalized.dat` and the associated `Vega` stellar-line database files.
2. Set the first line of `SLD.config` to `examples/` and verify the remaining parameters.
3. Verify that `Hitran_database.par` is present.
4. Run `./CLTELL_linux` from the repository root.
5. Compare `examples/vega_normalized.no_tell` with `examples/vega_normalized.dat`.

A successful build and launch do **not**, by themselves, establish scientific equivalence between the Windows and Linux executables. Validate the numerical results against a reference spectrum before using them in a publication.
